- Replaced the original OLA stage, and then a rejected Signalsmith implementation, with official **Rubber Band Library 4.0.0**.

## 3. Tape and Pitch/Time latency — fixed and accepted

### Root cause

Tape resampling originally ran in the decoder, upstream of the 8-second source ring. Changing Tape pitch therefore affected only newly decoded audio; the old-pitch buffered audio had to drain first. Mode switches could also resample already-shaped audio again through Rubber Band.

The earlier `--latency-probe` reported ring depth at parameter application, not the time when output audio actually reflected the change, so its 85 ms claim missed the audible problem.

### Fix

- Decoder now writes raw media frames to the source ring.
- `TapeResampler` runs at the audible edge in the stretcher thread, alongside `RubberBandStage` in `PitchChain`.
- No FFmpeg reinitialization, source-ring flush, fade, or audio drop is needed for live parameter changes.
- Real-output measurements: Tape engage about 105 ms, retune about 97 ms; Pitch/Time engage and retune roughly 116–175 ms. Previous Tape delay was seconds (about 2.2 s in one measurement, up to ring depth).
- Tape/pitch/tempo behavior was subsequently accepted by David as **flawless**.

## 4. Parameters window — original behavior restored

- Separate Tape Speed and Pitch/Time cards; inactive card is dimmed and inert, and clicking it activates that engine.
- Pitch/Time has independent pitch and time-stretch controls plus formant preservation and per-card reset.
- Tape uses whole semitones and maps `st` to `2^(st/12)`, coupling pitch and speed.
- Pitch/Time pitch uses whole semitones; tempo uses 1% steps and a bipolar track centered at 100%.
- Wheel detents advance exactly one displayed unit. JS `Math.round` semantics are reproduced (`-2.5 -> -2`), unlike Rust `f32::round`.
- Deliberate small deviation from Electron: the original tempo engine received continuous values while displaying whole percent; the Rust port applies the displayed 1% grid coherently.
- New-track behavior resets source and shared parameters to defaults unless **Lock Parameters Across Tracks** is enabled. Explicit loads, next/previous, and automatic playlist advance use the same path; seek/restart of the current track does not reset.
- The lock preference persists in `user.json`; transient playback parameters do not.
- Checkpoint before later tracker/MIDI integration: 34 SoundApp tests passed and release build succeeded. Dark screenshots: `target/params_tape.png`, `target/params_pitchtime.png`.

## 7. Current architecture

```text
FFmpeg source -> raw source ring -> audible-edge Tape / Rubber Band -> 80 ms output ring
Tracker/MIDI  -> raw source ring (100 ms high-water) -> raw passthrough ----^
                                                             -> cpal callback, fades, volume, DSP tap
```

Native source controls are source-specific. Shared Tape/Rubber Band post-processing is FFmpeg-only, matching the Electron reference; the decoder publishes effective parameters on every source switch so locked audio parameters cannot leak into native playback or remain neutralized when returning to FFmpeg.

## 8. Native control latency — tracker and MIDI verified

Native controls are applied in the source engine before the PCM source ring, so an uncapped ring retains old-parameter audio. The current cap is:

- `NATIVE_HIGH_WATER_SECS = 0.100` for Openmpt/Midi producers.
- FFmpeg retains its 8-second buffer for disk/SMB decoding.
- Nothing is dropped on a parameter change.

The real-output tracker latency gate passes, as do the high-water refill test and tracker transport tests. The repeating-note MIDI real-output transpose gate now **passes**: audible latency ~280–300 ms against the 500 ms budget (2026-10-25), with the settle decided by Goertzel energy at the true fundamental (261.6 Hz grid) — see §11 for why the zero-crossing estimator alone cannot decide the plateau on this SoundFont.

## 11. Field performance testing (2026-10-25)

Built for real-world measurement on slower machines:

- **GUI-subsystem build:** `#![windows_subsystem = "windows"]` — no console window ever opens. `attach_parent_console()` (raw kernel32 FFI, zero deps) re-attaches to a launching terminal so harness output stays visible; piped/redirected stdout is detected via `GetStdHandle`/`GetFileType` and left untouched (measure.ps1 and `Start-Process -RedirectStandardOutput` capture normally). PowerShell 5.1 does **not** wait for GUI children on `&`-invocation and captures nothing — always redirect via `Start-Process`.
- **FPS console logging removed** in soundapp (whole counter machinery) and nui-demo (println only; the header badge stays).
- **`perf.rs` field log:** a handful of lines per session in `perf_log.txt` next to `user.json` — session marker with args, `first_frame_ms`, `audio_started_ms`, `track_ready_ms` (open request → decoder metadata, measured in `open_path`/`load_playlist_index`), and `frame_pacing` summaries every 10 s (frames + >66 ms intervals; >500 ms gaps count as new bursts, not stalls) with flushes on exit/auto-quit.
- **Zero-flash window creation fixed:** windows were created visible and only cloaked afterwards, so one white `WM_ERASEBKGND` frame (winit registers no class brush) could reach the compositor before the cloak. `Renderer::new` now creates every window hidden, applies the theme-colored class brush (`Theme::dark`/`light` `.base`, was hardcoded `#131313`) plus first fill and cloak while invisible, and `request_reveal()` maps the window after the first presented frame. Warm first-frame latency unchanged (~280 ms; first run after a rebuild reads ~1 s from cold driver caches — compare warm runs only).
- **`measure.ps1`**: quotes arguments with spaces (PS 5.1 `Start-Process -ArgumentList` never quotes — `Y:\Test Files\...` was splitting), samples **GPU utilization** for the process pid via GPU Engine counters (locale-safe set lookup; `-NoGpu` to disable), clamps the CPU delta when the app exits mid-window, and still reports stdout timings.
- **Test audio volume:** live-stream tests play through the real device at 10% volume (`Shared.volume` `#[cfg(test)]`); gate detection uses zero crossings / partial energy, both amplitude-independent.
- **Frameless style hardened (2026-10-25 field report):** winit keeps `WS_CAPTION` in the styles of undecorated windows and hides the caption only via its `WM_NCCALCSIZE` client-area override. On one Win11 machine that override desynced at reveal (suspected DPI/display change right at first show) — the caption strip rendered over the client, displacing content and every hitbox by the caption height, bottom rows cut off. `Renderer::ensure_frameless()` now strips `WS_CAPTION|WS_SYSMENU` at creation and re-strips after any winit flag refresh (one style probe per present, writes only on change). Cost: the fake shadow from winit's `+1px` NCCALCSIZE margin trick is replaced by the real DWM corner/shadow treatment; Aero-snap drag behavior may degrade slightly. Retest on the reporter machine pending.
- **Dist package:** `scripts/make-dist.ps1` assembles `dist/soundapp_r/` + zip — exe, the 9 runtime DLLs build.rs stages, `soundfonts/default.sf2` (scanned from the portable config folder beside `user.json` by `soundfont_list`), `metronome/*.wav` (resolved exe-relative first since 2026-10-25, `metronome_asset()`, synthesized-click fallback), and `licenses/` notices. Smoke test launches the dist standalone and requires `audio started` on stdout. The 30.8 MB SoundFont is still not vendored into the repository; the dist pulls it from the reference tree.

### MIDI gate findings (recorded for future sessions)

- The reference SoundFont's sustaining presets are inconsistent: GM 16 "Drawbar Organ" and all probed presets decay to silence within ~1 s under note-off/on retrigger cycles, and decay hard even held (piano). Only **GM 19 (Church Organ) with repeated same-key NOTE-ONS (no note-offs)** sustains at constant amplitude — the gate's generated MIDI (`gen_steady_tone_midi`) uses that pattern. The note-off/on decay looks like an engine scheduling quirk worth keeping in mind for real MIDI files with fast repeated notes.
- Zero-crossing window estimates swing ±30% on this preset at constant pitch (tremolo/chorus modulation) — the gate's plateau decision therefore uses Goertzel power at the fundamental (261.6 Hz grid; 1.5× is a non-integer multiple, so the new probe frequency carries no pre-change energy): settled = tail new-fundamental median > 4× its pre-change (leakage) level AND old-fundamental median < 0.25× its pre-change level. Measured: old 1.19e-7 → 8.8e-10 (134× drop), new 4.4e-9 → 1.0e-7 (23× rise), latency ~297 ms.

Opening Mixer pauses the main player; closing Mixer destroys its engine. Short stems end into silence until the transport loops.
- Mixer UI transport/time/VU now reads live engine state. Stable engine slots survive strip removal. The `+` target appends and a strip target replaces only that stem; folder drops expand recursively on the scanner thread, and multi-file additions share one transport resync. Mixer drop jobs are deferred rather than lost by ordinary playlist-scan coalescing. Empty-Mixer rendering and fader/pan/seek geometry were fixed.
- Parameters cards now use `nui_card_auto`: the column's final cursor measures intrinsic content height, and each card background is resized to `content + padding + gaps` instead of clipping against guessed heights. ## 13. Multi-zone file drop reliability (2026-10-26)

- **Root cause:** winit 0.30's Windows `IDropTarget` discards the coordinate in `DragOver` and `Drop`, emitting only `HoveredFile` on entry. Cursor movement is suppressed during the OLE drag loop, so the Rust overlay stayed on the first zone and the subsequent action used stale geometry.
- **Fix:** NUI exposes `cursor_position_in_window` and `primary_mouse_button_down`; SoundApp polls the OS cursor at full frame cadence while a file drag is active, refreshes it on entry and drop, and clears the overlay if the pointer leaves the client area or the mouse button is released. Rendering and drop dispatch share one `drop_zone_at` mapping.
- **Clarity:** the active zone now has a stronger fill/border and changes its label to `Release to add`, `Release to replace`, or `Release for Mixer`.
- **Verification:** a synthetic OLE file drag crossed all three zones with each highlight confirmed by desktop capture; release over Add logged `drop zone=Add cursor=(264,108)` and loaded the track. Unit test covers the three coordinate partitions. A `drop zone=… cursor=… path=…` line is appended to `perf_log.txt` for field diagnosis.

## 14. Mixer synchronization telemetry and mute fix (2026-10-26)

- **Mute/solo desync root cause:** the cpal callback skipped every inaudible stem entirely, so its ring stopped being consumed while the shared transport advanced. Unmuting resumed at the stale sample. Muted/inaudible stems now always consume their next stereo frame; only their contribution to the mix/meter is suppressed.
- **Transport telemetry:** each slot publishes played frames, underrun frames, ring depth, and start offset. The callback resets these counters on every transport generation (seek/reloop/stem reload), so drift is `transport_frames_since_generation - played_frames`.
- **SYNC DEBUG panel:** `Ctrl+Shift+D` opens a window-bounded table with state, drift ms, buffer ms, underrun ms, and audible source time per stem. Rows scroll when a large stem set exceeds the panel; `COPY` writes a text snapshot to the clipboard. `--sync-debug` opens it at launch for capture/harness runs.
- **Verification:** a 13-stem real-media run showed `0.0 ms` drift across every stem before mute, during one-stem mute, and after unmute; the muted stem's source clock continued with the others. `muted_stem_keeps_consuming_transport_frames` covers the regression.

## 15. Startup reveal latency (2026-10-26)

- **Root cause:** winit's `focus_window()` simulates an Alt key tap and re-enters foreground activation; on this system it blocked the first render for **~810 ms**. Re-stripping winit's frame bits at uncloak added another blocking `SWP_FRAMECHANGED`.
- **Fix:** strip the frame styles in `request_reveal()` while the window is still cloaked, and replace winit's focus helper with a direct `SetWindowPos(HWND_TOP)` + `SetForegroundWindow` path. The cloaked dark-background/first-fill guard remains, so reveal is still flash-free.
- **Measured:** first frame dropped from **~950 ms to ~160–195 ms** on warm GPU runs. A short-lived attempt to map/present a backdrop before backend initialization was rejected: it stalled the first real swap, so the fast path stays inside the existing cloak-and-reveal flow.

## 16. Per-window renderer split (2026-10-26)

- **Default routing:** the player and static utility windows (Parameters, Settings, Help) use the CPU Softbuffer backend; Monitoring and Mixer use the GPU OpenGL backend. `--backend cpu|gpu` remains a global benchmark/debug override.
- **Rationale (measured):** player first frame **~30 ms CPU vs ~280 ms GPU**; working set **52 MB vs 136 MB**. At 60 Hz, Monitoring costs **48% of one core on CPU vs 15% on GPU**; Mixer costs **35% vs 19%**.
- **Consequence:** the main window is visible almost immediately, while hardware acceleration is paid only when an animation-heavy secondary window opens. The obsolete main-window `B` toggle was removed from Help/README.
